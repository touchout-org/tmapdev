DotPad Haptics & Responsiveness Experiment

Fixed 60x40 tactile display, no pan or zoom. Move the cursor with the arrow keys or the Dot Pad's cursor dots (3/2/5/6 = left/up/down/right). Write/pacing strategy is fixed to what DotTMAP itself uses in production (single full-frame write, no redundant clear pass, coalesced at a fixed interval) — that tuning work is done; this page is for the two things that aren't: haptic feedback parameters, and replacing the old software-timed cursor-acceleration hack with the SDK's real key-down/key-up events for hold-to-repeat movement.

This App works best in Chrome. Please switch to Chrome so you can connect to the Dot Pad.

Cursor repeat rate (hold-to-repeat, driven by real key-down/key-up)

Holding a direction (keyboard arrow key, or the Dot Pad's own cursor dot) moves the cursor once immediately on key-down, then pauses 200ms before repeating at the interval selected below, for as long as the key stays down. Releasing the key (key-up) stops the repeat immediately — no timeout guessing, no "how long has it been since the last press" heuristics. Repeating only ever runs while that's the only key or dot held: pressing a second key/dot cancels the repeat immediately, and resuming afterward always requires releasing everything and starting a fresh key-down — this is deliberate, so this repeat behavior never fights with other combos (panning, zooming, etc.) that reuse the same cursor keys/dots alongside others.

Haptics

The Dot Pad's vibrator is on/off only — there is no intensity/amplitude parameter in the protocol, only pulse timing. requestVibrator(onMs, offMs, repeatCount): on ms and off ms are each truncated to 10ms resolution by the device firmware; repeat count is silently clamped to 1–5 by the SDK no matter what's requested. Edit the fields and press "Test vibration" to feel a configuration, or press dot 1 on the Dot Pad itself — its key-down triggers the same test with the current settings.
